## 2. ご依頼: 動作確認用の AWS 環境

実環境での確認のため、**影響のないテスト用の IPSet** をご用意いただけますでしょうか。

スクリプトは既存の IPSet を操作します（IPSet 自体の作成は行いません）。

| 項目 | 必要な内容 |
|---|---|
| IPSet | **IPv4版**を1つ。名前は任意（例: `crawler-test`） |
| スコープ | `REGIONAL`（ALB/API Gateway配下）か `CLOUDFRONT` か。**どちらかをお教えください** |
| リージョン | `CLOUDFRONT` の場合は `us-east-1` 固定。それ以外はご指定のリージョン |
| IAM権限 | `wafv2:ListIPSets` / `wafv2:GetIPSet` / `wafv2:UpdateIPSet` の3つ |
| プロファイル | 使用する AWS プロファイル名 |
| 確認事項 | **その IPSet が本番の Web ACL から参照されていないこと** |

### 確認の手順

いただいた環境で、以下の順に実施して結果をご報告します。

| | 内容 | 確認できること |
|---|---|---|
| 1 | 中身を読むだけ | 接続・権限・設定が正しいか |
| 2 | 模擬実行（書き込まない） | 差分の計算が正しいか |
| 3 | 実際に書き込む | 反映が成功するか |
| 4 | 書き込み結果を読み直して照合 | **登録された内容が取得内容と1件単位で一致するか** |

4 まで通れば、本番適用の判断材料が揃います。
Bing での確認を推奨します（28件と少なく、2年以上内容が変わっていないため照合しやすい）。

## 3. ご確認: 実行基盤について

定期実行の方式をご確認させてください。**現状は Linux の crontab を前提に作成しています。**

### 選択肢

| 方式 | 追加作業 | 備考 |
|---|---|---|
| **A. Linux の crontab** | **不要**。すぐ運用開始できる | 現状の想定。サーバ管理の延長で扱える |
| B. ECS スケジュールタスク | 小（コンテナ化のみ） | スクリプトはそのまま使える。サーバ不要 |
| C. Lambda | **大（作り直し）** | 下記の理由により、実質的に別物を作ることになります |

### C（Lambda）をご希望の場合について

Lambda は bash を標準でサポートしていません。
そのため Python 等への書き直しが必要で、**現在のスクリプトは使えなくなります**。

それに加えて、以下が失われます。

- **手元で1行実行して確かめる**という運用ができなくなる
  （「Google の最新IPだけ見たい」「この1件だけ追加したい」が、その場でできる状態を重視して作っています）
- 障害時に手で叩いて切り分ける、という対処ができなくなる

Lambda をご希望であれば対応しますが、**上記を踏まえたうえでのご判断**をお願いします。
サーバ運用の中で回せるのであれば、A が最も手数が少なく、障害時の対処もしやすいと考えます。

**サーバレスにしたいが作り直しは避けたい**場合は、B（ECS スケジュールタスク）が中間案になります。
現在のスクリプトをそのままコンテナに入れて動かせます。
